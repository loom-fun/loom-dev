port / publish

From a GGUF on Hugging Face to a row on the board.

Your coding agent does the work. loom-skills teach it to port the model to AMD Loom, validate it against llama.cpp ROCm and write the model card from the benchmark report. Then you upload the package to Hugging Face. There's no form to fill in.

01install

Install loom-skills into your agent

The skills work in Claude Code, Codex and Pi. Install all of them together, since they share scripts, then start a fresh agent session. You don't install Loom by hand: the skills install hrx-loom (the Loom compiler, runtime and loom-serve, built from ROCm/hrx-system) from PyPI into ~/loom/.venv, and download the latest llama.cpp ROCm build as the reference.

shell
$ npx skills add loom-fun/loom-skills --skill '*' -g
No Node.js? Use the Python 3.12+ installer instead. It installs the skills for all three agents; add --agent codex to pick one.
shell
$ git clone https://github.com/loom-fun/loom-skills
$ python3 loom-skills/scripts/install_skills.py
02port

Port, optimize and benchmark in one prompt

The agent ports the checkpoint (loom-port-llm/port.sh), qualifies it against llama.cpp ROCm (qualify.sh: gates, baselines, roofline), optimizes it within the model's roofline budget and finalizes it (finalize.sh: full gates, audit, report). It never stops to ask, except to accept a gated model's license.

agent prompt
> /loom Port, validate and optimize <hf-gguf>.
Budget: add a time or a target at the end, like "…for 3 hours." or "…until decode is 50 % faster than llama.cpp.". The roofline step tells you up front if a target is out of reach. In Codex the skill is $loom, and in Pi it's /skill:loom.
03upload

Generate the card and publish to Hugging Face

The agent generates info.json and README.md from the run's own logs with the loom-skills card scripts, then uploads the package: the .loom programs, model.json and model.json.lock, the tokenizer and the card. The GGUF itself isn't copied, since loom-fetch pulls it from its original repo and checks its sha256. Log in to Hugging Face once first:

shell
$ pip install -U huggingface_hub
$ hf auth login
agent prompt
> /loom Generate the Hugging Face model card for this port and upload the package to <hf-org>/<model>-loom.
Every number on the card has to come from the report. A value without evidence renders as not measured or no evidence, and that's what keeps the index trustworthy.
04listed

Show up on HRX Loom

The index reads public Hugging Face models tagged loom and loom-serve. On the next refresh your model gets a leaderboard row, a detail page and a quick start. Anyone can then serve it with hrx-loom:

shell
$ pip install "hrx-loom[hf]==0.1.0"
$ loom-fetch https://huggingface.co/<hf-org>/<repo>/resolve/main/model.json --output=<name>
$ loom-serve --model=<name>/model.json --device=amdgpu --memory_bytes=<bytes>
Always pass --memory_bytes, for example --memory_bytes=17gb: it caps weights, KV pool and workspace. The server answers OpenAI-style requests on 127.0.0.1:8080. To update a listed model, rerun the benchmark and ask your agent to regenerate and re-upload the card.

  • hrx-loomLoom SDK from ROCm/hrx-system, on PyPI
  • loom-fetchfetch a package and its upstream GGUF

  • hfupload the package to Hugging Face
requirements
  • Linux x86-64 with glibc 2.39 or newer (Ubuntu 24.04+), or Windows 11 with Git Bash.
  • An AMD GPU. Developed on Strix Halo (gfx1151, 128 GB).
  • Python 3.12+ with venv, and git. Node.js only for npx skills.
  • An agent that loads skills: Claude Code, Codex or Pi.
  • A Hugging Face account with a write token, to publish.
