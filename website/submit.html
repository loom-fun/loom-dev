Submit a model

From GGUF to the leaderboard
in one afternoon.

There's no form to fill in. Port the model with loom-skills, upload the package to Hugging Face with the card the skills generate, and Loom Dev picks it up from its tags.

  1. 1

    Install loom-skills

    They work in any agent that supports skills: Claude Code, Cursor, Codex and more. Claude Code is the one they were developed with.

    terminal
    npx skills add loom-fun/loom-skills
    lightbulbNo Node? Clone loom-skills and run install.sh. It copies the skills into ~/.agents/skills and links them into ~/.claude/skills.
  2. 2

    Port, optimize and benchmark

    One prompt runs the whole pipeline: port, qualify against llama.cpp ROCm, optimize within the roofline budget, then the full gates and a report. It only stops to ask about a gated-model license.

    agent prompt
    > /loom get <hf-org>/<model> working on loom-serve, optimize it, and report the performance relative to llamacpp rocm
    timerWant more speed? Add a time or a target, like "…optimize it for 3 hours…" or "…until decode is 50 % faster than llama.cpp…". The roofline step tells you up front if a target is out of reach.
  3. 3

    Generate the model card

    README.md and info.json are generated from the run's own logs, never written by hand. The quickest way is to ask your agent to "generate the Hugging Face model card for this port". Under the hood, loom-benchmark runs:

    terminal
    # the card scripts from your loom-skills install
CARD=~/.agents/skills/loom-benchmark/scripts/card

# 1. evidence from the benchmark run
python $CARD/make_info.py perf --perf-log bench/perf_log.jsonl --llamacpp-build bNNNN -o ev_perf.json
python $CARD/make_info.py gates bench/gates.json -o ev_gates.json

# 2. info.json (schema loom-card/1), then the README rendered from it
python $CARD/make_info.py build PKG --repo <you>/<model>-loom --memory-bytes N \
  --output <name> --evidence ev_perf.json ev_gates.json -o PKG/info.json
python $CARD/render_card.py PKG/info.json -o PKG/README.md
    verified_userA value with no evidence shows as "not measured" or "no evidence". That's fine, and it's what keeps the leaderboard honest.
  4. 4

    Upload to Hugging Face

    Push the whole package: the .loom programs, model.json and its lock file, the tokenizer, and the generated card. The GGUF itself isn't copied; loom-fetch pulls it from its original repository and checks its sha256.

    terminal
    pip install -U huggingface_hub
hf auth login
hf repo create <you>/<model>-loom --repo-type model
hf upload <you>/<model>-loom PKG .
    sellThe generated card already carries the loom and loom-serve tags in its front matter. Keep them; they're how Loom Dev finds you.
  5. 5

    Watch it show up

    Loom Dev indexes public Hugging Face models that carry the Loom tags and an info.json with schema loom-card/1. On the next refresh your model gets a card, a spot on the leaderboard and a row in the heatmap. To update it, rerun the benchmark, regenerate the card and upload README.md and info.json again:

    terminal
    hf upload <you>/<model>-loom PKG . --include README.md info.json

sellTags Loom Dev looks for

loomloom-serve ggufstrix-halospeculative-decodingvision

The first two are required. The rest are added by make_info.py when they apply and power the filters.

FAQ

Good questions, straight answers.

My port is slower than llama.cpp on some workloads. Can I still submit?

Yes, please do. Plenty of models on Loom Dev lose on long-context prefill and win on decode. The heatmap shows both, and a slower number today is a target for the next optimization run.

Can I edit the numbers on my card?

No. Cards are rendered from info.json, and info.json is built from benchmark evidence. To change a number, rerun the benchmark and regenerate the card.

How is the ranking computed?

The overall score is the geometric mean of Loom's speedup over llama.cpp across every metric the model was measured on: decode at short, 2k and 32k context, prefill on 1k to 32k documents, and 4-stream aggregate decode. Missing metrics are skipped, not counted as zero.

Which architectures can loom-skills port?

The starter kit covers dense transformers and Qwen3.5-style gated delta-net hybrids, with vision projectors and speculative-decoding drafters where the model has them. Other architectures go through the hand-port playbook in loom-port-llm, which takes longer and leaves less time for optimization.

What do "no evidence" gates mean?

The gate applies to the model, but no recorded run covers it yet. Rerunning the full gates (finalize.sh, or a nightly DevLab run) fills them in. The "All gates pass" badge needs every applicable gate to pass.

How do I take my model off Loom Dev?

Remove the loom tag from the card, or make the repository private. It drops off on the next refresh.

The skills got something wrong. Where do I report it?

Open an issue or a PR on loom-skills. The loom-improve skill even lets your agent run fresh-agent trials to fix the skills themselves: "your goal is to improve the loom skill at X".
