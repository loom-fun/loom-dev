publish / guide

From a GGUF on Hugging Face to a row on the board.

There's no form to fill in. Port the model with loom-skills, upload the package with the card the skills generated, and the index picks it up from its tags.

01install

Install loom-skills into your agent

Works with any agent that supports skills: Claude Code, Cursor, Codex and others. The skills were developed with Claude Code.

shell
$ npx skills add loom-fun/loom-skills
No Node? Clone loom-skills and run install.sh. It copies the skills into ~/.agents/skills and links them into ~/.claude/skills.
02port

Port, optimize and benchmark in one prompt

The agent runs port, qualify, optimize and finalize without stopping, within the model's roofline budget. It only asks about gated-model licenses. Loom and the llama.cpp ROCm reference are downloaded for you.

agent prompt
> /loom get <hf-org>/<model> working on loom-serve, optimize it, and report the performance relative to llamacpp rocm
Budget: add a time or a target, like "…optimize it for 3 hours…" or "…until decode is 50 % faster than llama.cpp…". The roofline step tells you up front if a target is out of reach.
03card

Generate the model card from the run

README.md and info.json are generated, never hand-written. The easiest way is to ask your agent to "generate the Hugging Face model card for this port". Under the hood:

shell
# card scripts from your loom-skills install
CARD=~/.agents/skills/loom-benchmark/scripts/card

# 1. evidence from the benchmark run
python $CARD/make_info.py perf --perf-log bench/perf_log.jsonl --llamacpp-build bNNNN -o ev_perf.json
python $CARD/make_info.py gates bench/gates.json -o ev_gates.json

# 2. info.json (schema loom-card/1), then README.md rendered from it
python $CARD/make_info.py build PKG --repo <you>/<model>-loom --memory-bytes N \
  --output <name> --evidence ev_perf.json ev_gates.json -o PKG/info.json
python $CARD/render_card.py PKG/info.json -o PKG/README.md
A value without evidence renders as not measured or no evidence. That's expected, and it's what keeps the index trustworthy.
04upload

Upload the package to Hugging Face

Push the .loom programs, model.json and its lock file, the tokenizer and the generated card. The GGUF itself isn't copied: loom-fetch pulls it from its original repo and checks its sha256.

shell
pip install -U huggingface_hub
hf auth login
hf repo create <you>/<model>-loom --repo-type model
hf upload <you>/<model>-loom PKG .
The generated front matter already carries the loom and loom-serve tags. Keep them; they're how the index finds you.
05listed

Show up on loom/dev

The index reads public Hugging Face models with the Loom tags and an info.json of schema loom-card/1. On the next refresh your model gets a row, a detail page and a quick start. To update it, rerun the benchmark, regenerate the card and upload those two files again:

shell
hf upload <you>/<model>-loom PKG . --include README.md info.json

faq

Questions people ask before their first port.

Which architectures can loom-skills port?

The starter kit covers dense transformers and Qwen3.5-style gated delta-net hybrids, with vision projectors and speculative-decoding drafters where the model has them. Anything else goes through the hand-port playbook in loom-port-llm. That takes longer and leaves less of the budget for optimization.

My port is slower than llama.cpp on some workloads. Should I still publish?

Yes. The index shows every workload, including the ones where llama.cpp is faster. A working, verified port is the useful part, and a slow metric is a clear target for the next optimization run.

Can I edit the numbers on my card?

No. Cards are rendered from info.json, which is built from benchmark evidence. To change a number, rerun the benchmark and regenerate the card.

What does "no evidence" mean on a gate?

The gate applies to the model, but no recorded run covers it yet. Running the full gates (finalize.sh, or a nightly DevLab run) fills it in.

How is the leaderboard ordered?

By the geometric mean of Loom's throughput over llama.cpp's across every metric the model was measured on: decode at short, 2k and 32k context, prefill on 1k to 32k documents, and 4-stream aggregate decode. Missing metrics are skipped. You can re-sort by any column.

How do I remove my model?

Remove the loom tag from the card, or make the repository private. It drops off on the next refresh.

The skills got something wrong. Where do I report it?

Open an issue or a PR on loom-skills. The loom-improve skill lets your agent run fresh-agent trials to fix the skills themselves: "your goal is to improve the loom skill at X".
