How a model gets woven

One prompt. Four steps.
Zero hand-typed numbers.

loom-skills turns your coding agent into a porting crew. It works within the model's roofline time budget, from about 25 minutes for a 0.8B model to about 70 for a 30B dense one.

conversion_path

Port

Pick a GGUF that fits, generate the Loom kernels, build at the native context, and run the kernel tests and a smoke test.

loom-port-llm · ~1 min
fact_check

Qualify

Find the fastest llama.cpp ROCm build, run the correctness gates against it, and compute the roofline targets.

loom-benchmark · ~10 min
rocket_launch

Optimize

Measure, ablate, change, verify. A rate-of-approach controller decides whether to keep going, pivot or stop.

loom-optimize · roofline budget
verified

Finalize

Full gates including a full-context probe, final perf, an audit, and a generated report and model card.

finalize.sh · card + info.json

House rules

Fast is fun. Honest is better.

balance

Same GGUF, same box

Both engines run the unmodified checkpoint on the same machine, against the fastest llama.cpp ROCm build available.

precision_manufacturing

Generated, never typed

Cards and info.json come straight from the benchmark logs. A value with no evidence shows as not measured.

trending_down

Losses included

If llama.cpp is faster on a workload, Loom Dev says so. Correctness gates that failed or never ran are shown too.
