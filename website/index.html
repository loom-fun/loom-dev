01 / how it works

Four scripted steps, with your agent's judgment only where it's needed.

One prompt runs the whole pipeline without stopping. It asks only when a model is gated behind a license. The whole job fits in the model's roofline budget: in recent trials, about 25 minutes for a 0.8B model and about 70 for a 30B dense one.

02 / what you get

A complete model server, not a demo.

The chat glue is derived from the model's own Jinja chat template and verified against it, so the port behaves the way the model was trained to be used.

ctx

Native context length

Built at the model's full context, for example 40,960 tokens for Qwen3-0.6B and 262,144 for Qwen3.5-0.8B.

tools

Tool calling, in the model's format

OpenAI-style tools and tool_calls, rendered exactly the way the template expects.

think

Reasoning with an on/off switch

Thinking models keep their reasoning, and you can turn it off per request.

cache

History reuse between turns

Agent loops don't re-prefill the whole conversation on every turn.

sample

Per-request sampling

temperature, top_p, top_k and seed, checked against llama.cpp's first-token distribution.

api

OpenAI-compatible endpoint

loom-serve answers /v1/chat/completions, so existing clients work unchanged.

03 / correctness

The reference is llama.cpp on the same GGUF, never a hand-written model.

Every port is checked by the loom-benchmark gates. Each gate records the run that produced it, and a gate with no run shows as "no evidence" rather than a guess.

gates.sh

Rails built into the skills

  • Never serves a model whose weights exceed the GPU's memory budget. A 104 GiB model once hard-crashed a 128 GB machine.
  • Always passes --memory_bytes to loom-serve.
  • Asks before running any downloaded binary, except Loom from PyPI and lemonade-sdk/llamacpp-rocm releases.
  • Caches the llama.cpp reference outputs, so re-running gates on an optimized build only costs the Loom side.
  • Generates the model card from the logs. No number on a card is typed by hand.

05 / publish

Ported something? Put it on the board.

There's no form. Upload the package to Hugging Face with the card the skills generated. Models tagged loom and loom-serve with an info.json show up here.

step a

Generate the card

Ask your agent to generate the Hugging Face card for the port. loom-benchmark builds info.json from the logs and renders README.md from it.

python $CARD/render_card.py PKG/info.json -o PKG/README.md
step b

Upload the package

The .loom programs, model.json and its lock file, the tokenizer and the card. The GGUF stays in its original repo.

hf upload <you>/<model>-loom PKG .
step c

Show up here

The card's front matter already carries the tags. On the next index refresh your model gets a row, a detail page and a quick start.
